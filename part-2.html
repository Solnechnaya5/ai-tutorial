17. JSON

JSON — текстовий формат для передачі даних між програмами. Майже всі API, зокрема API мовних моделей, приймають і віддають JSON.

1Як виглядає

{
  "name": "Yulia",
  "age": 28,
  "skills": ["python", "sql"],
  "is_active": true,
  "manager": null
}

Схоже на словник Python, але це текст. Щоб із ним працювати, його треба перетворити на словник.

2Відповідність типів

JSONPython
object {}dict
array []list
stringstr
numberint або float
true / falseTrue / False
nullNone

У JSON рядки й ключі — тільки в подвійних лапках. Кортежів і множин немає.

3json.loads: текст → Python

import json

text = '{"name": "Yulia", "skills": ["python", "sql"]}'

data = json.loads(text)

print(type(data))
print(data["skills"][0])
<class 'dict'> python

4json.dumps: Python → текст

import json

user = {"name": "Zoë", "age": 28, "is_active": True}

print(json.dumps(user))
print(json.dumps(user, ensure_ascii=False, indent=2))
{"name": "Zoë", "age": 28, "is_active": true} { "name": "Zoë", "age": 28, "is_active": true }
  • ensure_ascii=False — лишити не-ASCII символи (кирилицю, ë, emoji) читабельними, а не ë.
  • indent=2 — красиві відступи.

Як запам'ятати: s на кінці — це string. loads читає з рядка, dumps пише в рядок.

5Файли: load і dump

import json

config = {"model": "small", "temperature": 0.2}

with open("config.json", "w", encoding="utf-8") as file:
    json.dump(config, file, ensure_ascii=False, indent=2)

with open("config.json", "r", encoding="utf-8") as file:
    loaded = json.load(file)

print(loaded["model"])
small

7Безпечний доступ до вкладених даних

В API-відповідях потрібне значення часто лежить глибоко, а деяких полів може не бути.

8JSON у відповіді моделі

Модель часто просять відповісти JSON-ом. Вона повертає текст, і цей текст треба розібрати. Він може виявитися зламаним, тож try обов'язковий.

18. HTTP-запити

HTTP — спосіб, яким програми спілкуються через інтернет. Твоя програма надсилає запит, сервер повертає відповідь. Так працює і виклик мовної моделі.

1З чого складається запит

  • URL — адреса, куди звертаємося.
  • Метод — що хочемо зробити: GET отримати, POST надіслати.
  • Headers — службові дані: формат, ключ доступу.
  • Body — самі дані (у POST).

У відповіді приходять статус-код, заголовки й тіло, найчастіше JSON.

2GET

Бібліотеку спершу треба встановити: pip install requests.

import requests

response = requests.get("https://api.github.com/users/python", timeout=10)

print(response.status_code)

data = response.json()
print(data["name"])
200 Python

.json() одразу перетворює тіло відповіді на словник. Це те саме, що json.loads(response.text).

3Статус-коди

401немає ключа або він неправильний

Просте правило: 2xx — успіх, 4xx — помилка у твоєму запиті, 5xx — помилка на боці сервера.

6Headers і Bearer token

Більшість API пускає лише з ключем. Зазвичай його передають у заголовку Authorization.

import os
import requests

api_key = os.environ["MY_API_KEY"]

headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}

response = requests.get("https://api.example.com/v1/models", headers=headers, timeout=10)

Правило. Ключ ніколи не пишуть прямо в коді. Його кладуть у змінну середовища і читають через os.environ. Ключ, який потрапив на GitHub, вважай украденим.

7raise_for_status

requests не кидає виняток, якщо сервер відповів 404 чи 500. Щоб помилка не пройшла непоміченою:

import requests

response = requests.get("https://api.github.com/users/this-user-does-not-exist-12345", timeout=10)
response.raise_for_status()

8timeout

Без timeout програма може чекати на відповідь вічно. Вказуй його завжди. Для мовних моделей бери більше, 30–60 секунд, бо вони відповідають довго.

9Усе разом

import requests

def fetch_json(url, params=None):
    try:
        response = requests.get(url, params=params, timeout=10)
        response.raise_for_status()
        return response.json()
    except requests.exceptions.Timeout:
        print("The server did not respond in time")
    except requests.exceptions.HTTPError as error:
        print(f"HTTP error: {error.response.status_code}")
    except requests.exceptions.RequestException as error:
        print(f"Connection problem: {error}")
    return None

data = fetch_json("https://api.github.com/users/python")

if data:
    print(data["public_repos"])

19. Regex (re)

Регулярний вираз — це шаблон для пошуку в тексті. Не конкретне слово, а опис: «три цифри, дефіс, дві цифри».

1Перший пошук

import re

text = "Order #4521 is paid"

match = re.search(r"\d+", text)

print(match.group())
4521
  • \d — будь-яка цифра.
  • + — одна або більше.
  • r"..." — «сирий» рядок. У ньому \ лишається собою. Шаблони завжди пиши з r.

Пастка. Якщо нічого не знайдено, re.search повертає None, і .group() впаде з AttributeError. Спершу перевіряй: if match:.

2Основний синтаксис

СимволЗначення

\wлітера, цифра або _
\sпробіл, табуляція, перенос рядка
.будь-який символ, крім переносу рядка
+один або більше разів
*нуль або більше разів
?нуль або один раз
{3}, {2,4}рівно 3 рази; від 2 до 4

4Групи

Дужки виділяють частину збігу, яку можна дістати окремо.

import re

text = "Date: 2026-10-05"

match = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)

if match:
    print(match.group())
    print(match.group(1))
    year, month, day = match.groups()
    print(day, month, year)
2026-10-05 2026 05 10 2026

Якщо в шаблоні є групи, findall повертає саме їх:

import re

text = "name=Yulia; city=Kyiv"

print(re.findall(r"(\w+)=(\w+)", text))
[('name', 'Yulia'), ('city', 'Kyiv')]

5Жадібність

+ і * захоплюють якомога більше. Знак питання після них робить пошук «лінивим»: якомога менше.

import re

text = "<b>one</b> and <b>two</b>"

print(re.findall(r"<b>(.+)</b>", text))
print(re.findall(r"<b>(.+?)</b>", text))
['one</b> and <b>two'] ['one', 'two']

6Перевірка формату

import re

def is_email(text):
    return re.fullmatch(r"[\w.+-]+@[\w-]+\.[\w.]+", text) is not None

print(is_email("yulia@example.com"))
print(is_email("yulia@example"))
True False

7Прапорці

  • re.IGNORECASE — не зважати на регістр.
  • re.DOTALL — крапка збігається і з переносом рядка.
  • re.MULTILINE — ^ і $ працюють для кожного рядка.

20. Функції вищого порядку та замикання

У Python функція — це звичайне значення. Її можна покласти у змінну, передати в іншу функцію або повернути з функції. На цьому тримаються декоратори.

1Функція як значення

def shout(text):
    return text.upper() + "!"

action = shout

print(action("hello"))
HELLO!

Без дужок — це сама функція. З дужками — її виклик.

Функція, яка приймає або повертає іншу функцію, називається функцією вищого порядку.

def apply(func, value):
    return func(value)

print(apply(len, "Python"))
print(apply(shout, "hooray"))
6 HOORAY!

2lambda

Коротка функція без імені, в один вираз.

double = lambda x: x * 2

print(double(5))
10

Це те саме, що def double(x): return x * 2. Окремо lambda у змінну кладуть рідко. Її пишуть прямо там, де треба передати маленьку функцію.

3sorted з key

key — функція, яка каже, за чим сортувати.

docs = [
    {"title": "Report", "score": 0.72},
    {"title": "Contract", "score": 0.91},
    {"title": "Letter", "score": 0.55},
]

best = sorted(docs, key=lambda doc: doc["score"], reverse=True)

for doc in best:
    print(doc["title"], doc["score"])
Contract 0.91 Report 0.72 Letter 0.55

Так само працюють min() і max(): max(docs, key=lambda doc: doc["score"]).

4map і filter

numbers = [1, 2, 3, 4, 5]

squares = list(map(lambda n: n ** 2, numbers))
even = list(filter(lambda n: n % 2 == 0, numbers))

print(squares)
print(even)
[1, 4, 9, 16, 25] [2, 4]

map застосовує функцію до кожного елемента, filter лишає ті, для яких функція дала True. Обидві повертають не список, тому результат загортають у list().

У Python частіше пишуть те саме генератором списку: [n ** 2 for n in numbers].

5Замикання

Функція, створена всередині іншої, пам'ятає змінні зовнішньої навіть після того, як та закінчилася.

def make_multiplier(factor):
    def multiply(number):
        return number * factor
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))
print(triple(10))
20 30

double «замкнула» в собі factor = 2.

6Декоратор

Декоратор — функція, яка бере функцію і повертає її обгорнуту версію. Так до будь-якої функції можна додати поведінку, не змінюючи її коду.

import functools
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.2f} s")
        return result
    return wrapper

@timer
def slow_task():
    time.sleep(0.5)
    return "done"

print(slow_task())
slow_task: 0.50 s done
  • @timer над функцією — те саме, що slow_task = timer(slow_task).
  • *args, **kwargs пропускають будь-які аргументи до справжньої функції.
  • functools.wraps зберігає ім'я та опис оригінальної функції.

7retry

API інколи падає на рівному місці. Декоратор повторює виклик кілька разів, з кожним разом чекаючи довше.

import functools
import time

def retry(attempts=3, delay=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as error:
                    if attempt == attempts:
                        raise
                    wait = delay * 2 ** (attempt - 1)
                    print(f"Attempt {attempt} failed: {error}. Waiting {wait} s")
                    time.sleep(wait)
        return wrapper
    return decorator

@retry(attempts=3, delay=1)
def call_api():
    ...

Тут три рівні функцій, бо декоратор сам приймає параметри. Зовнішня бере налаштування, середня — функцію, внутрішня виконує роботу.

8memoize

Запам'ятати результат, щоб не рахувати вдруге. Для платних запитів до моделі це пряма економія.

import functools

@functools.lru_cache(maxsize=1000)
def get_embedding(text):
    print(f"Computing for: {text}")
    return len(text)

get_embedding("hello")
get_embedding("hello")
get_embedding("world")
Computing for: hello Computing for: world

Другий виклик з тим самим аргументом узяв відповідь із кешу. Аргументи мають бути незмінними: рядки, числа, кортежі.

9rate limit

API дозволяє обмежену кількість запитів за хвилину. Декоратор стежить, щоб між викликами минала пауза.

import functools
import time

def rate_limit(calls_per_second):
    interval = 1 / calls_per_second
    last_call = 0

    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            nonlocal last_call
            wait = interval - (time.monotonic() - last_call)
            if wait > 0:
                time.sleep(wait)
            last_call = time.monotonic()
            return func(*args, **kwargs)
        return wrapper
    return decorator

@rate_limit(calls_per_second=2)
def call_api(prompt):
    ...

nonlocal дозволяє змінювати змінну зовнішньої функції. Без нього Python створив би нову локальну last_call.

Коротка шпаргалка

ЗаписЗначення

map(f, items)застосувати f до кожного
filter(f, items)лишити, де f дає True

21. Віртуальні середовища та pip

Віртуальне середовище — окрема папка з власним набором бібліотек для одного проєкту. Проєкти не заважають один одному, а список залежностей можна передати іншій людині.

1Навіщо

Проєкту А потрібна бібліотека версії 1, проєкту Б — версії 2. Якщо ставити все в один загальний Python, один із проєктів зламається. З окремим середовищем у кожного свої версії.

2Створення

У терміналі, в папці проєкту:

python -m venv .venv

З'явиться папка .venv з копією Python і місцем для бібліотек.

3Активація

ДеКоманда
Windows, PowerShell.venv\Scripts\Activate.ps1
Windows, cmd.venv\Scripts\activate.bat
Git Bashsource .venv/Scripts/activate
macOS, Linuxsource .venv/bin/activate

Після активації на початку рядка термінала з'явиться (.venv). Вийти із середовища: deactivate.

Якщо PowerShell не дає запустити скрипт. Один раз виконай Set-ExecutionPolicy -Scope CurrentUser RemoteSigned і спробуй знову.

У VS Code: Ctrl+Shift+P → «Python: Select Interpreter» → обери той, що з .venv. Тоді редактор сам активує середовище в нових терміналах.

4pip

pip install requests
pip install requests==2.32.3
pip install --upgrade requests
pip uninstall requests
pip list
pip show requests

Усе встановлюється в активне середовище. Якщо (.venv) не видно, пакет піде в загальний Python.

5requirements.txt

Файл зі списком бібліотек проєкту. Папку .venv нікому не передають, передають цей файл.

requests==2.32.3
python-dotenv==1.0.1

Зберегти поточний набір:

pip freeze > requirements.txt

Встановити все зі списку на іншому комп'ютері:

pip install -r requirements.txt

6Секрети у файлі .env

Ключі API зберігають у файлі .env поруч із кодом:

ANTHROPIC_API_KEY=sk-ant-...
TELEGRAM_TOKEN=123456:ABC...

Читають через бібліотеку python-dotenv:

import os
from dotenv import load_dotenv

load_dotenv()

api_key = os.environ["ANTHROPIC_API_KEY"]

7Що не потрапляє в Git

У файл .gitignore одразу додай:

.venv/
.env
__pycache__/

.venv важить сотні мегабайтів і відновлюється з requirements.txt. .env містить секрети.

8Порядок дій для нового проєкту

  1. Створити папку, відкрити її в терміналі.
  2. python -m venv .venv
  3. Активувати середовище.
  4. pip install ... потрібні бібліотеки.
  5. pip freeze > requirements.txt
  6. Створити .gitignore і .env.

22. Git / GitHub

Git зберігає історію змін у проєкті. GitHub — сайт, де ця історія лежить в інтернеті, щоб над кодом можна було працювати командою і показувати його роботодавцю.

1Основні поняття

СловоЗначення
repositoryпапка проєкту разом з історією змін
commitзбережений знімок проєкту з підписом
branchокрема лінія розробки
mergeзлиття однієї гілки в іншу
remoteкопія репозиторію на сервері, наприклад на GitHub

2Перше налаштування

git config --global user.name "Yulia"
git config --global user.email "you@example.com"

Робиться один раз на комп'ютері.

3Перший commit

git init
git status
git add les_4.py
git add .
git commit -m "Add lesson 4 exercises"
  • git init — зробити папку репозиторієм.
  • git status — що змінилося. Запускай часто.
  • git add — обрати, які зміни підуть у наступний commit. Крапка означає «всі».
  • git commit -m — зберегти знімок з описом.

Зміни проходять три стани: файл змінено → додано через add → збережено через commit.

4Історія

git log --oneline
git diff
git diff --staged

git diff показує ще не додані зміни, --staged — ті, що вже додані через add.

5.gitignore

Список файлів і папок, які Git має ігнорувати.

.venv/
.env
__pycache__/
*.log
.vscode/

Пастка. .gitignore не діє на файли, які вже потрапили в історію. Якщо ключ API вже закомічено, видалити файл мало. Ключ треба відкликати й створити новий.

6Гілки

git switch -c feature/add-tests
git branch
git switch main
  • git switch -c name — створити гілку й перейти на неї.
  • git branch — список гілок.
  • git switch name — перейти на наявну.

Правило командної роботи: кожна задача — у своїй гілці. У main напряму не комітять.

7merge

git switch main
git merge feature/add-tests

Якщо в обох гілках змінено ті самі рядки, Git зупиниться і позначить конфлікт просто у файлі:

<<<<<<< HEAD
print("version from main")
=======
print("version from the branch")
>>>>>>> feature/add-tests

Треба лишити правильний варіант, прибрати позначки, потім git add і git commit.

8GitHub

Створи порожній репозиторій на github.com, потім:

git remote add origin https://github.com/username/project.git
git push -u origin main

Далі щоденна робота:

git pull
git push
  • git push — відправити свої commit на GitHub.
  • git pull — забрати чужі зміни з GitHub.
  • git clone address — скачати чужий репозиторій разом з історією.

9Pull request

  1. git switch -c feature/name
  2. Зробити зміни, git add, git commit.
  3. git push -u origin feature/name
  4. На GitHub натиснути «Compare & pull request», описати, що зроблено.
  5. Колега дивиться код, лишає коментарі.
  6. Після схвалення — «Merge».
  7. Локально: git switch main, git pull.

10Хороший commit

  • Один commit — одна логічна зміна.
  • Опис англійською, у наказовому способі: «Add retry decorator», «Fix token counting».
  • «fix», «update», «asdf» — погані описи. Через місяць не зрозумієш, що там було.

23. Тести та логування

Тест — це код, який перевіряє твій код. Лог — це записи про те, що програма робила. На співбесіді джуна часто питають: «Як ти перевіряєш, що код працює?» Відповідь «запускаю і дивлюся» не підходить.

1Навіщо тести

  • Змінюєш функцію, запускаєш тести й одразу бачиш, чи нічого не зламалось.
  • Тест показує, як функцію задумано використовувати. Це жива документація.
  • У командах pull request без тестів часто не приймають.

2assert

assert condition, "message" нічого не робить, якщо умова правдива, і кидає AssertionError, якщо хибна.

def add_tax(price, rate=0.2):
    return round(price * (1 + rate), 2)


assert add_tax(100) == 120.0
assert add_tax(100, rate=0) == 100, "Without tax the price stays the same"
print("All good")
All good

3pytest

Найпопулярніша бібліотека для тестів. Тести лежать у файлах test_*.py, а кожен тест — це функція, назва якої починається з test_.

# prices.py
def add_tax(price, rate=0.2):
    if price < 0:
        raise ValueError("price must be positive")
    return round(price * (1 + rate), 2)
# test_prices.py
import pytest
from prices import add_tax


def test_default_rate():
    assert add_tax(100) == 120.0


def test_zero_rate():
    assert add_tax(50, rate=0) == 50


def test_negative_price():
    with pytest.raises(ValueError):
        add_tax(-1)
pip install pytest
pytest            # all tests in the folder
pytest -v         # with each test's name
pytest -k zero    # only tests whose name contains zero
test_prices.py::test_default_rate PASSED test_prices.py::test_zero_rate PASSED test_prices.py::test_negative_price PASSED

4Що тестувати

  • Звичайний випадок: типові дані.
  • Межі: порожній список, нуль, один елемент, дуже довгий рядок.
  • Помилки: неправильні дані мають кидати зрозумілий виняток.

Один тест перевіряє одну річ. Назва тесту каже, що саме: test_empty_list_returns_zero.

5Як тестувати код з LLM

Справжня модель повільна, платна й щоразу відповідає трохи інакше. Тому в тестах її підміняють заготовленою відповіддю (mock). Перевіряють те, що робить твій код: як він розбирає відповідь, що робить з помилкою, який промпт збирає.

def parse_sentiment(answer):
    answer = answer.strip().lower()
    if answer not in ("positive", "negative", "neutral"):
        return "unknown"
    return answer


def test_parse_with_spaces():
    assert parse_sentiment("  Positive\n") == "positive"


def test_parse_garbage():
    assert parse_sentiment("I think it's good") == "unknown"

У задачах курсу є FakeClient. Це саме така підміна моделі: він повертає відповіді, які ти йому дала.

6logging замість print

print годиться для навчальних скриптів. У сервісі потрібні рівні важливості, час і можливість вимкнути зайве без правок коду.

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
)
logger = logging.getLogger(__name__)

logger.debug("Not shown: level is below INFO")
logger.info("Service started")
logger.warning("Response took %.1f s", 4.2)
logger.error("Model returned empty answer")
2026-10-19 12:00:01,123 INFO __main__: Service started 2026-10-19 12:00:01,124 WARNING __main__: Response took 4.2 s 2026-10-19 12:00:01,124 ERROR __main__: Model returned empty answer

8Помилка з повним traceback

try:
    result = 10 / 0
except ZeroDivisionError:
    logger.exception("Calculation failed")

logger.exception пише рівень ERROR і додає повний текст помилки. Викликай його тільки всередині except.

Безпека. Ніколи не пиши в лог ключі API, паролі й особисті дані користувачів. Логи читає багато людей і сервісів.
