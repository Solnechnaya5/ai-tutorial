38. Async Python

Асинхронний код не стоїть без діла, поки чекає на відповідь мережі. За час одного очікування він встигає почати інші задачі.

1Навіщо

Запит до моделі триває кілька секунд, і майже весь цей час програма просто чекає. Якщо запитів десять, звичайний код чекатиме на кожен по черзі. Асинхронний відправить усі одразу й чекатиме на них одночасно.

Async допомагає там, де є очікування: мережа, база, файли. Важкі обчислення він не пришвидшує.

Бот чи вебсервіс обслуговує багато людей водночас, тому aiogram і FastAPI побудовані на async.

2async def і await

import asyncio

async def greet():
    print("Починаю")
    await asyncio.sleep(1)
    print("Готово")

asyncio.run(greet())
Починаю Готово
  • async def створює корутину — функцію, яка вміє ставати на паузу.
  • await — місце паузи: «чекаю тут, а поки можна робити інше».
  • asyncio.run() запускає все. Викликається один раз, у точці входу програми.

await можна писати тільки всередині async def.

3Пастка: забутий await

import asyncio

async def get_answer():
    return 42

async def main():
    result = get_answer()
    print(result)

asyncio.run(main())
<coroutine object get_answer at 0x...> RuntimeWarning: coroutine 'get_answer' was never awaited

Виклик корутини без await нічого не виконує, а лише створює об'єкт. Правильно: result = await get_answer().

4asyncio.gather

Запускає кілька корутин одночасно й чекає на всі.

import asyncio
import time

async def fetch(name, seconds):
    print(f"{name}: старт")
    await asyncio.sleep(seconds)
    print(f"{name}: готово")
    return name

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
        fetch("C", 2),
    )
    print(results)
    print(f"{time.perf_counter() - start:.1f} с")

asyncio.run(main())
A: старт B: старт C: старт B: готово A: готово C: готово ['A', 'B', 'C'] 2.0 с

По черзі це зайняло б 5 секунд. Одночасно — 2, стільки триває найдовша задача. Результати повертаються в тому порядку, у якому передано корутини.

5Не блокуй

Усі корутини працюють в одному потоці. Якщо одна викличе звичайну «довгу» функцію, зупиняться всі.

БлокуєЗаміна для async
time.sleep(1)await asyncio.sleep(1)
requests.get(url)await client.get(url) з httpx
Anthropic()AsyncAnthropic()

Якщо асинхронної версії бібліотеки немає, блокуючу функцію можна винести в окремий потік: await asyncio.to_thread(func, arg).

import asyncio
import httpx

async def get_repos(client, user):

7Async-запити до LLM

import asyncio
from anthropic import AsyncAnthropic

client = AsyncAnthropic()

async def classify(review):
    response = await client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=10,
        system="Відповідай одним словом: positive, negative або neutral.",
        messages=[{"role": "user", "content": review}],
    )
    return response.content[0].text

async def main():
    reviews = ["Все супер!", "Жахливий сервіс", "Отримав у вівторок"]
    results = await asyncio.gather(*[classify(review) for review in reviews])
    for review, label in zip(reviews, results):
        print(label, "—", review)

asyncio.run(main())

Зірочка перед списком розпаковує його в окремі аргументи для gather.

9Помилки в gather

Якщо одна корутина впаде, gather кине її виняток, і решта результатів загубиться. Щоб отримати все:

results = await asyncio.gather(*tasks, return_exceptions=True)

for result in results:
    if isinstance(result, Exception):
        print(f"Помилка: {result}")
    else:
        print(result)

39. REST API — практика

REST — це набір домовленостей про те, як будувати HTTP API. Якщо їх дотримано, чужий API зрозумілий без довгого читання документації.

1Ресурси й endpoints

API будується навколо ресурсів: користувачі, замовлення, документи. Endpoint — це адреса ресурсу плюс метод.

https://api.example.com/v1/users/42/orders?status=paid&limit=10
└──────── base URL ───────┘└──── path ────┘└─── query params ───┘
  • У шляху — іменники в множині: /users, /orders.
  • Дію задає метод, а не адреса. Не /getUsers, а GET /users.
  • /users/42 — конкретний користувач, 42 тут path-параметр.
  • Фільтри, сортування, сторінки — у query-параметрах після ?.

2Methods

Разом ці дії називають CRUD: Create, Read, Update, Delete.

GET нічого не змінює на сервері, його можна повторювати безпечно. Повторний POST створить дублікат.

6CRUD з Python

jsonplaceholder.typicode.com — безплатний тестовий API для тренувань. Змін він не зберігає, але відповідає як справжній.

import requests

BASE = "https://jsonplaceholder.typicode.com"

# Read
posts = requests.get(f"{BASE}/posts", params={"userId": 1}, timeout=10).json()

# Create

# Update

7Пагінація

Великі списки API віддає сторінками. Щоб забрати все, запити повторюють, доки сторінки не закінчаться.

import requests

def fetch_all(url):
    items = []
    page = 1
    while True:
        response = requests.get(url, params={"_page": page, "_limit": 50}, timeout=10)
        response.raise_for_status()
        batch = response.json()
        if not batch:
            break
        items.extend(batch)
        page += 1
    return items

print(len(fetch_all("https://jsonplaceholder.typicode.com/comments")))
500

Назви параметрів у кожного API свої: page, offset, cursor. Дивись документацію.

8Як читати документацію API

  1. Authentication. Як отримати ключ і куди його класти.
  2. Base URL. Спільна частина всіх адрес.
  3. Endpoint. Метод, шлях, обов'язкові параметри.
  4. Приклад відповіді. Де лежить потрібне поле.
  5. Rate limits. Скільки запитів дозволено за хвилину.
  6. Errors. Які коди повертає і що вони означають.

Запит можна спробувати без коду: командою curl у терміналі, у застосунку Postman або в розширенні REST Client для VS Code.

curl -H "Authorization: Bearer $TOKEN" "https://api.example.com/v1/users?limit=5"

9Власний API

Правила, якщо проєктуєш свій:

  • Іменники в множині, методи замість дієслів в адресі.
  • Правильні статус-коди. Не 200 з текстом «помилка» всередині.
  • Однакова будова помилок у всіх endpoints.
  • Версія в адресі: /v1/.... Тоді зміни не зламають старих клієнтів.
  • Перевірка всіх вхідних даних.

Як це написати на Python — у темі 41, FastAPI.

6GROUP BY

Ділить рядки на групи й рахує агрегат для кожної окремо.

SELECT user_id, COUNT(*) AS orders_count, SUM(amount) AS total
FROM orders
GROUP BY user_id;
user_id orders_count total 1 2 1700 2 1 300

AS дає колонці ім'я. WHERE фільтрує рядки до групування, HAVING фільтрує вже готові групи:

SELECT user_id, SUM(amount) AS total
FROM orders
WHERE status = 'paid'
GROUP BY user_id
HAVING SUM(amount) > 1000;

7JOIN

З'єднує рядки двох таблиць за спільним ключем.

SELECT users.name, orders.amount
FROM users
JOIN orders ON orders.user_id = users.id;
Юля 500 Юля 1200 Олег 300

Ірини тут немає, бо в неї немає замовлень. LEFT JOIN лишає всі рядки з лівої таблиці, навіть без пари:

SELECT u.name, COUNT(o.id) AS orders_count
FROM users AS u
LEFT JOIN orders AS o ON o.user_id = u.id
GROUP BY u.name;
Юля 2 Олег 1 Ірина 0

8INSERT, UPDATE, DELETE

UPDATE users SET city = 'Харків' WHERE id = 2;

DELETE FROM orders WHERE status = 'new';

Пастка. UPDATE і DELETE без WHERE змінюють або видаляють усі рядки таблиці. Спершу напиши SELECT з тією самою умовою і подивись, що саме потрапить під дію.

10SQL із Python

SQLite вбудований у Python і зберігає всю базу в одному файлі. Для навчання нічого встановлювати не треба.

import sqlite3

connection = sqlite3.connect("shop.db")
connection.row_factory = sqlite3.Row
cursor = connection.cursor()

cursor.execute("""
    CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        city TEXT,
        age INTEGER
    )
""")

cursor.execute(
    "INSERT INTO users (name, city, age) VALUES (?, ?, ?)",
    ("Юля", "Київ", 28),
)
connection.commit()

cursor.execute("SELECT name, age FROM users WHERE city = ?", ("Київ",))

for row in cursor.fetchall():
    print(row["name"], row["age"])

connection.close()
Юля 28

Зміни зберігаються тільки після commit().

SQL injection. Ніколи не вставляй значення в запит через f-рядок. Якщо користувач введе '; DROP TABLE users; --, база це виконає. Значення передавай окремо, через ?, як у прикладі.

41. FastAPI

FastAPI — фреймворк для створення власних API на Python. Асинхронний, сам перевіряє дані й сам будує документацію.

1Перший застосунок

pip install "fastapi[standard]"

Файл main.py:

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"message": "Привіт"}

Запуск:

fastapi dev main.py

Сервер стартує на http://127.0.0.1:8000 і перезапускається, коли ти зберігаєш файл. Словник, який повернула функція, FastAPI сам перетворює на JSON.

За адресою /docs лежить інтерактивна документація. Звідти можна викликати кожен endpoint просто в браузері.

2Routes

Декоратор задає метод і шлях. Функція під ним обробляє запит.

@app.get("/users")
def list_users():
    return [{"id": 1, "name": "Юля"}]

@app.post("/users")
def create_user():
    return {"id": 2}

@app.delete("/users/{user_id}")
def delete_user(user_id: int):
    return {"deleted": user_id}

3Path і query параметри

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"id": user_id}

@app.get("/search")
def search(q: str, limit: int = 10):
    return {"query": q, "limit": limit}
  • Параметр у фігурних дужках шляху — path-параметр.
  • Інші параметри функції стають query-параметрами: /search?q=python&limit=5.
  • Параметр зі значенням за замовчуванням необов'язковий.

Підказки типів тут працюють насправді. FastAPI перетворить "42" з адреси на число, а на /users/abc сам відповість помилкою 422.

4Pydantic: тіло запиту

Будову вхідних даних описують класом. FastAPI перевіряє запит за цим описом ще до того, як викличе твою функцію.

from pydantic import BaseModel, Field

class ReviewRequest(BaseModel):
    text: str = Field(min_length=1, max_length=2000)
    language: str = "uk"

@app.post("/analyze")
def analyze(request: ReviewRequest):
    return {"length": len(request.text), "language": request.language}

Якщо надіслати запит без text, відповідь буде 422 з поясненням, якого поля бракує. Перевірку руками писати не треба.

5Модель відповіді

class ReviewResponse(BaseModel):
    sentiment: str
    score: float

@app.post("/analyze", response_model=ReviewResponse)
def analyze(request: ReviewRequest):
    return {"sentiment": "positive", "score": 0.9, "debug": "це поле не потрапить у відповідь"}

response_model відсікає зайві поля й показує будову відповіді в документації.

6Помилки

from fastapi import HTTPException

users = {1: "Юля", 2: "Олег"}

@app.get("/users/{user_id}")
def get_user(user_id: int):
    if user_id not in users:
        raise HTTPException(status_code=404, detail="Користувача не знайдено")
    return {"id": user_id, "name": users[user_id]}

7Async endpoints

import httpx

@app.get("/github/{user}")
async def github(user: str):
    async with httpx.AsyncClient() as client:
        response = await client.get(f"https://api.github.com/users/{user}", timeout=10)
    return {"repos": response.json()["public_repos"]}
  • async def — коли всередині є await: запит до моделі, бази, іншого API.
  • Звичайний def — коли код блокуючий. FastAPI сам запустить його в окремому потоці.

Пастка. Блокуючий виклик (requests, time.sleep) усередині async def зупиняє сервер для всіх користувачів, доки не закінчиться.

6Інтеграція з LLM

from aiogram import F
from aiogram.enums import ChatAction
from anthropic import AsyncAnthropic

llm = AsyncAnthropic()
histories = {}

@dp.message(Command("reset"))
async def reset(message: Message):
    histories.pop(message.from_user.id, None)
    await message.answer("Розмову очищено.")

@dp.message(F.text)
async def chat(message: Message):
    history = histories.setdefault(message.from_user.id, [])
    history.append({"role": "user", "content": message.text})

    await message.bot.send_chat_action(message.chat.id, ChatAction.TYPING)

    try:
        response = await llm.messages.create(
            model="claude-haiku-4-5",
            max_tokens=1000,
            system="Ти дружній асистент. Відповідай коротко, українською.",
            messages=history[-20:],
        )
    except Exception:
        history.pop()
        await message.answer("Не вдалося отримати відповідь. Спробуй ще раз.")
        return

    answer = response.content[0].text
    history.append({"role": "assistant", "content": answer})

    await message.answer(answer[:4096])
  • histories — словник, де ключ — номер користувача. У кожного своя розмова.
  • setdefault повертає значення за ключем, а якщо його немає — спершу створює.
  • history[-20:] — надсилаємо лише останні повідомлення, щоб контекст не ріс без меж.
  • ChatAction.TYPING показує «друкує...», поки модель думає.
  • AsyncAnthropic, а не Anthropic. Синхронний клієнт зупинив би бота для всіх.

7Обмеження Telegram

  • Одне повідомлення — до 4096 символів. Довшу відповідь треба різати на частини.
  • Бот не може написати людині першим. Спершу вона має надіслати /start.
  • Є ліміт на кількість повідомлень за секунду.
async def send_long(message, text, size=4096):
    for start in range(0, len(text), size):
        await message.answer(text[start:start + size])

43. Docker

Docker пакує застосунок разом з усім, що йому потрібно для роботи: Python потрібної версії, бібліотеки, налаштування. Такий пакунок однаково працює на будь-якому комп'ютері.

1Яку проблему вирішує

«У мене працює, а на сервері ні». Інша версія Python, бракує бібліотеки, інша операційна система. Docker прибирає цю різницю: усюди запускається те саме середовище.

2Images і containers

registryсховище образів, наприклад Docker HubPyPI

З одного образу можна запустити багато контейнерів. Контейнер ізольований: у нього свої файли й своя мережа.

На Windows потрібен застосунок Docker Desktop.

3Dockerfile

Файл Dockerfile без розширення, у корені проєкту:

FROM python:3.12-slim

COPY . .

CMD ["fastapi", "run", "main.py", "--port", "8000"]

requirements.txt копіюється окремо й раніше за решту коду не випадково. Docker кешує кожен крок. Якщо змінився лише код, бібліотеки не встановлюються заново, і збирання триває секунди.

.venv/

Правило. Секрети в образ не кладуть. Образ можна скачати й розпакувати, і ключ дістануть. Ключі передають під час запуску.

Усе, що контейнер записав у себе, зникає разом із ним. Щоб дані пережили перезапуск, папку контейнера прив'язують до сховища зовні.

8docker-compose

Справжній сервіс — це кілька контейнерів: API, база, черга. Compose описує їх усі в одному файлі compose.yaml і запускає однією командою.

services:
  api:
    build: .
    ports:
      - "8000:8000"
    env_file: .env
    environment:
      DATABASE_URL: postgresql://app:secret@db:5432/app
      REDIS_URL: redis://redis:6379/0
    depends_on:
      - db
      - redis

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - db_data:/var/lib/postgresql/data

  redis:
    image: redis:7

volumes:
  db_data:

docker compose logs -f api
docker compose down

Важливо. Усередині compose контейнери бачать один одного за назвою сервісу. Адреса бази — db, а не localhost. У контейнері localhost — це він сам.

9Контейнеризація AI-сервісу

  • Ключі API — через змінні середовища, не в образі.
  • Векторна база й завантажені документи — у volume.
  • Важкі моделі (наприклад, для embeddings) роблять образ великим. Якщо можна, бери embeddings через API.
  • Точні версії в requirements.txt, щоб образ збирався однаково сьогодні й через пів року.
  • Endpoint /health, щоб було чим перевірити, що сервіс піднявся.

44. Фонові та заплановані задачі

Довгу роботу не виконують під час запиту користувача. Її відкладають у фон, а користувачеві відповідають одразу. Регулярну роботу запускають за розкладом.

1Навіщо

  • Обробити 200-сторінковий PDF для RAG — це хвилини. Запит стільки не чекає, з'єднання обірветься.
  • Згенерувати 500 описів товарів — це години.
  • Щоранку о 9:00 надсилати звіт у Slack. Тут запиту від користувача немає взагалі.

Схема для довгої роботи:

клієнт → API: «оброби файл»
API → клієнт: «прийнято, task_id = abc123»      (миттєво)
           ...задача виконується у фоні...
клієнт → API: «як там abc123?»
API → клієнт: «готово, ось результат»

2Background jobs у FastAPI

Найпростіший варіант, вбудований у FastAPI. Задача запускається після того, як відповідь уже надіслано.

from fastapi import BackgroundTasks, FastAPI

app = FastAPI()

def index_document(path: str):
    print(f"Індексую {path}")

@app.post("/documents")
async def upload(path: str, background_tasks: BackgroundTasks):
    background_tasks.add_task(index_document, path)
    return {"status": "accepted"}

Підходить для коротких і не критичних задач. Якщо сервер перезапуститься, задача загубиться, і повторів немає.

3Celery і Redis

Celery — система черг задач для серйозної фонової роботи. Складається з трьох частин:

ЧастинаРоль
Застосуноккладе задачу в чергу
Brokerзберігає чергу. Найчастіше це Redis
Workerокремий процес, що бере задачі з черги й виконує

Redis — швидка база, що тримає дані в оперативній пам'яті у вигляді «ключ → значення». Крім черг, її використовують для кешу й лічильників.

pip install "celery[redis]"
docker run -d -p 6379:6379 redis:7

4Задача Celery

Файл tasks.py:

import time

from celery import Celery

celery_app = Celery(
    "tasks",
    broker="redis://localhost:6379/0",
    backend="redis://localhost:6379/1",
)

@celery_app.task
def index_document(path):
    time.sleep(10)
    return {"path": path, "chunks": 42}

Запуск worker в окремому терміналі:

celery -A tasks worker --loglevel=info

На Windows додай --pool=solo. У продакшні worker зазвичай працює в Docker на Linux.

5Виклик і результат

from celery.result import AsyncResult
from fastapi import FastAPI

from tasks import celery_app, index_document

app = FastAPI()

@app.post("/documents")
def upload(path: str):
    task = index_document.delay(path)
    return {"task_id": task.id}

@app.get("/tasks/{task_id}")
def status(task_id: str):
    result = AsyncResult(task_id, app=celery_app)
    if result.ready():
        return {"status": result.status, "result": result.result}
    return {"status": result.status}
  • .delay(...) не виконує функцію, а кладе задачу в чергу й одразу повертає її номер.
  • backend — місце, де зберігаються результати.
  • Статуси: PENDING, STARTED, SUCCESS, FAILURE.

8Розклад у Celery

Celery Beat — окремий процес, який у потрібний час кладе задачі в чергу.

from celery.schedules import crontab

celery_app.conf.timezone = "Europe/Kyiv"
celery_app.conf.beat_schedule = {
    "daily-report": {
        "task": "tasks.send_daily_report",
        "schedule": crontab(hour=9, minute=0),
    },
    "sync-every-15-min": {
        "task": "tasks.sync_data",
        "schedule": 15 * 60,
    },
}
celery -A tasks beat --loglevel=info

Часовий пояс вказуй явно. Сервери зазвичай живуть за UTC, і «9:00» виявиться північчю або полуднем.

45. Інтеграції

Інтеграція — це з'єднання твого сервісу з чужим через його API. AI-сервіс стає корисним, коли працює там, де вже працюють люди: у таблицях, пошті, месенджерах.

1Спільна схема

Усі інтеграції будуються однаково:

  1. Отримати доступ: ключ, токен або сервісний акаунт.
  2. Знайти в документації потрібний endpoint.
  3. Зробити запит через SDK сервісу або через requests.
  4. Обробити помилки, ліміти й пагінацію.

import os

6Типовий AI-сценарій

Прочитати відгуки з таблиці, визначити тональність моделлю, записати результат назад і надіслати підсумок у Slack.

def process_reviews():
    rows = sheet.get_all_records()
    labels = []

    for row in rows:
        if row["Тональність"]:
            continue
        labels.append(classify(row["Відгук"]))

    if not labels:
        return

    start = len(rows) - len(labels) + 2
    sheet.update(
        range_name=f"D{start}:D{start + len(labels) - 1}",
        values=[[label] for label in labels],
    )

    positive = labels.count("positive")
    notify_slack(f"Оброблено {len(labels)} нових відгуків, позитивних: {positive}")

Результати записуються одним запитом, а не по клітинці. У Google API суворі ліміти на кількість запитів за хвилину.

Тут зроблено припущення, що необроблені відгуки йдуть підряд у кінці таблиці. Якщо це не так, записуй номер рядка разом із кожною міткою.

7Webhooks

Звичайна інтеграція: ти питаєш сервіс, чи є нове. Webhook навпаки: сервіс сам надсилає тобі запит, коли щось сталося.

from fastapi import FastAPI, Request

app = FastAPI()

  • Відповідай швидко. Довгу обробку виноси у фонову задачу (тема 44).
  • Перевіряй підпис запиту, якщо сервіс його надсилає. Інакше будь-хто зможе слати тобі підроблені події.
  • Та сама подія може прийти двічі. Обробка має це витримувати.

8Клієнт-обгортка

Уся робота з одним сервісом збирається в один клас. Решта коду не знає про адреси й токени.

import requests

class CRMClient:
    def __init__(self, token, base_url="https://api.crm.example.com/v1"):
        self.base_url = base_url
        self.session = requests.Session()
        self.session.headers["Authorization"] = f"Bearer {token}"

    def _get(self, path, **params):
        response = self.session.get(f"{self.base_url}{path}", params=params, timeout=15)
        response.raise_for_status()
        return response.json()

    def get_deals(self, status="open"):
        return self._get("/deals", status=status)

    def get_contact(self, contact_id):
        return self._get(f"/contacts/{contact_id}")

Зміниться API сервісу — правити доведеться один файл. А в тестах справжнього клієнта легко замінити підробним.

9На що зважати

  • Rate limits. На 429 — пауза й повтор. Сервіс часто сам каже, скільки чекати, у заголовку Retry-After.
  • Пагінація. Перша сторінка — це не всі дані.
  • Термін дії токенів. OAuth-токени живуть близько години, їх треба оновлювати.
  • Секрети. Тільки у змінних середовища.
  • Логи. Записуй, що надіслано і що отримано, але без токенів і персональних даних.

    with st.chat_message(message["role"]):
        st.write(message["content"])

if question:
    st.session_state.messages.append({"role": "user", "content": question})
    with st.chat_message("user"):
        st.write(question)

    with st.chat_message("assistant"):
        with st.spinner("Думаю..."):
            response = client.messages.create(
                model="claude-haiku-4-5",
                max_tokens=1000,
                temperature=temperature,

        st.write(answer)

    st.session_state.messages.append({"role": "assistant", "content": answer})
